# ADR-0088: Antigravity CLI Live Sessions, Session Label and optional Orca Chat delivery

Status: accepted
Date: 2026-11-26

Architecture snapshot: [docs/architecture/2026-11-26-agy-sessions-label-and-orca-delivery.md](../architecture/2026-11-26-agy-sessions-label-and-orca-delivery.md)

Amends ADR-0039 (Live Sessions and Host UI mods), ADR-0040 (Message delivery channels) and ADR-0082 (Antigravity CLI session records).

## Context

Users who run Antigravity CLI (`agy`) alongside Claude Code, Codex and Grok Build face two gaps:

1. **No Live Sessions or Session Label**: `agy` is a Main-only Family (ADR-0047) with Quota (ADR-0048, ADR-0082) and Session History (ADR-0082), but no Live Session reader. Running `agy` conversations do not appear in `sideby sessions` or the Panel's Sessions page, and neither a terminal `agy` session nor an Orca Antigravity Chat tab shows a Session Label or a one-click copyable Session Reference.
2. **No `sideby send` path to `agy`**: unlike Claude Code's message socket or Codex's `codex queue`, `agy` has no documented cross-process inbound channel, so users fall back to calling orchestrator tools by hand whenever they want two `agy` sessions (or a Claude session and an `agy` session) to communicate.

Tried with `agy` 1.5.18 and Orca 1.4.277 on macOS on 2026-11-26:

- `agy` plugins (`plugin.json`) bundle skills, rules, MCP servers, subagents and lifecycle hooks (`hooks.json`), with no JS TUI rendering API equivalent to Claude Code's mod API (`AbovePrompt`, `Pane`, `Toast`).
- Terminal `agy` supports custom `statusLine` (including `"stack_with_default": true`, which renders below the built-in bar) and `title` scripts executed via `sh -c` (`cmd /c` on Windows), piped a JSON state payload on stdin containing `conversation_id`, `conversation_title`, `agent_state` (`idle`, `working`, `tool_use`, `reviewing`, `error`), `cwd` and `transcript_path` (no `pid` or `procStart`). Both keys can be passed per-session via `agy --settings <file>`, which is never saved into `~/.gemini/antigravity-cli/settings.json`. Whether `--settings` merges keys inside `statusLine` or replaces the whole object is `UNVERIFIED` and must be checked on `agy` 1.5.18 before implementation.
- Orca distinguishes three surfaces: an Orca **terminal** (`ORCA_TERMINAL_HANDLE`), a local structured **Antigravity Chat** (`agy acp` with `ORCA_STRUCTURED_SESSION=1` and `ORCA_AGENT_SESSION_ID=<orcaSessionId>`), and Orca's separate-login managed backend (outside `~/.gemini/antigravity-cli/`). Local `agy acp` does not render `agy`'s TUI `statusLine` or terminal title and does not go through `sideby run`.
- Each running `agy` / `agy acp` process holds open `conversations/<id>.db` and `brain/<id>` handles. A long-lived `agy acp` process may hold several open conversation handles (earlier threads plus subagents), and two processes can hold overlapping handles; Orca also keeps the same `orcaSessionId` across `/clear`.
- Plain-text JSONL transcripts live at `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript.jsonl`, usable for `sideby send` read receipts without opening binary `conversations/<id>.db` files. Whether Orca-delivered messages keep `sideby message <id>` verbatim in `transcript.jsonl` is `UNVERIFIED` until tested on a live chat.
- `agy agentapi send-message <recipient_id> <content>` requires `ANTIGRAVITY_LS_ADDRESS` and an in-memory `ANTIGRAVITY_CSRF_TOKEN` from the running `agy` process (without them it fails with `ANTIGRAVITY_LS_ADDRESS is not set`); cross-process delivery between separate `agy` processes is `UNVERIFIED`, and sideby never reads private tokens or undocumented language-server endpoints.
- Orca provides `orca orchestration send --to orca_session_id:<id> --body-file <file> --json`, which delivers into an Orca Antigravity Chat without putting the message body on `argv`. However, Orca requires a real sender identity (without one it falls back to a single resolvable terminal or returns `no_active_sender_terminal`), may return `runtime_unavailable` / `outcome_unknown` after a mid-flight disconnect when delivery state is unknown, and may convert very large messages into a Chat pickup note.
- Orca plugins (`trusted-worker`, `engines.orca >= 1.4.248`) support updating a bottom `statusBarItems` entry and rendering a TSX `components` sidebar panel.

## Decision

1. **Antigravity CLI Live Session reader** (`src/families/agy/live-sessions.ts`, registered in internal `READERS`):
   - **Scope**: discovers local interactive `agy` TUI and local `agy acp` processes of the current user (v1 does not cover Orca's separate-login managed backend), skipping non-interactive or subcommand invocations (`-p`/`--print`/`--prompt`, `agentapi`, `mcp`, `plugin`, `update`, `install`, `models`, `agents`, `changelog`, `remote-control`, `mic-serve`).
   - **Primary source for `sideby run agy`**: reads `<state>/agy-live/<pid>.json` written by `sideby agy-statusline` (enforcing `ownedFolder` `0700`, regular mode-`0600` file, no symlinks, bounded read size, and matching `pid` + OS `procStart`). Maps `reviewing` -> `needs-you` (`host-waits`), `working` / `tool_use` -> `busy`, `idle` -> `idle`; stale entries past a freshness window decay status to `unknown` so an outdated `reviewing` never sticks. The reader stays strictly read-only (never deletes files during listing, including from read-only Panel `/api/sessions`); dead-PID cleanup runs only in `sideby run agy` launch/exit and `sideby agy-statusline` write paths.
   - **Candidate resolution for plain `agy` and Orca `agy acp`**: inspects `openFiles(pid)` (with bounded concurrency and candidate limit) for `conversations/<id>.db` or `brain/<id>`, batched into **one** read-only `conversation_summaries.db` query per listing under ADR-0082's WAL/immutable rule (keeping ADR-0082's documented WAL/SHM race exception). Filters to `parent_conversation_id = '' AND nesting_depth = 0`.
   - **Ambiguity and collision guard**: `lsof` + `last_modified_time` produces candidates only. When a process still holds multiple top-level candidates with no stronger identity signal, or when two running processes resolve to the same `conversation_id`, mark the affected row(s) `guessed: true` (never silently claiming an exact match or letting two rows collapse onto one non-guessed id). A session with a verified `conversation_id` but no Host title yet falls back to its workspace folder name (`CONTEXT.md` Session Label), rather than being dropped.
   - **Expected transcript path**: for every verified (non-guessed) `agy` Live Session with a validated `conversation_id`, always compute the deterministic transcript path `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript.jsonl` even if the file does not exist yet (so first-message receipts can still resolve to `read` once `agy` creates it).
   - **Orca surface separation, `Started From` and latency isolation**:
     - Orca terminal (`ORCA_TERMINAL_HANDLE`, no `ORCA_STRUCTURED_SESSION=1`): sets `startedFrom: 'orca'` and uses existing terminal tab-jump (`orcaTabs`), not Chat delivery.
     - Local Orca Antigravity Chat (`agy acp` with `ORCA_STRUCTURED_SESSION=1` and `ORCA_AGENT_SESSION_ID`): sets `startedFrom: 'orca'` and records `orcaSessionId` only when confirmed against Orca (`orca agent list --json`).
     - Optional `orca agent list --json` enrichment (confirming Chat ID and mapping `working` -> `busy`, `done` -> `idle`) runs under its own short timeout (e.g. 1.5 s) and short-lived cache, independent of `LIST_DEADLINE_MS` (8 s) and Panel's 3 s budget, so a slow or stopped Orca never drops `agy` rows.
2. **Terminal `agy` Session Label via `--settings`** (`agyMod`, config default `true`):
   - On interactive `sideby run agy` (never `-p`/`--print`, never `login`), `prepareLaunch` writes a session-scoped settings JSON under `<state>/agy-launch/` (enforcing `ownedFolder` `0700`, mode `0600`, no symlinks, cleaned up on normal exit and pruned on stale launch) and passes `--settings <file>` to `agy`, writing nothing into `~/.gemini/antigravity-cli/`.
   - **Config fidelity**: if the caller already passed `--settings` on the command line, skip injection rather than clobbering it. Read `~/.gemini/antigravity-cli/settings.json` read-only: if the user explicitly set `statusLine.enabled === false` or `title.enabled === false`, respect that disabled state; preserve user `padding` and `stack_with_default` properties; coordinate with `accountTitle` so sideby's OSC 0 title loop does not fight `agy`'s `title` script.
   - The temporary settings point enabled slots to internal sideby helper entries (`sideby agy-statusline` / `sideby agy-title`, exempt from user-facing skill coverage like `statusline-tap`).
   - When the user has no custom `statusLine`, sideby sets `"stack_with_default": true` so the Session Label (`agy:main · <title> · <shortId>`) renders below `agy`'s built-in status bar. When the user already configured a custom `statusLine` or `title`, the helper runs the verified original command **at most once** with a recursion guard (`SIDEBY_AGY_HELPER_ACTIVE=1`) and bounded timeout, passing the payload strictly on stdin (never interpolating titles, paths or text into shell strings) and appending the Session Label.
   - Because `agy` launches `statusLine` via `sh -c`, `process.ppid` inside the helper may be a shell rather than `agy`. The helper resolves the owning `agy` process via ancestor PID walk (or launch-time binding env var set by `sideby run agy`), looks up its OS `procStart`, and atomically writes only non-credential fields (`pid`, `procStart`, `conversationId`, `title`, `agentState`, `cwd`, `updatedAt`) to `<state>/agy-live/<pid>.json` (never `email`, `plan_tier` or any token).
3. **Dual-ID addressing, Panel isolation and optional Orca Chat delivery** (`src/families/agy/deliver.ts`, registered in internal `DELIVERERS`):
   - **Canonical ID and public surface**: `LiveSession.sessionId` always stays `agy`'s own `conversation_id`, keeping `sideby sessions`, `sideby history`, `sessions copy`, `sessions open-run`, receipts, `Reply:` and `handedOverFrom` consistent.
   - `schemas/sessions.json` (`sideby sessions --json`, CLI only) adds optional `orcaSessionId` (`schemaVersion: 1` preserved) so `mods/orca/` can correlate the active Chat. The Panel's `/api/sessions` response uses an explicit field allowlist that omits `orcaSessionId` (consistent with ADR-0039 item 7 keeping Orca handles on the server side); Panel delivery resolves it server-side.
   - `selectSession` (shared by `send`, `sessions copy` and `sessions open-run`) accepts **only** the exact prefixed alias `orca_session_id:<id>` (never a bare Orca UUID, avoiding collision with `conversation_id`). `sideby messages --to` keeps its existing receipt-based filtering for accounts, host session IDs and prefixes (so exited sessions and multi-session accounts keep working), and resolves a live session only when given an explicit `orca_session_id:<id>` alias.
   - **Sender identification**: when `sideby send` runs inside an `agy` session and `senderSession` parent-PID walk finds no match (e.g. tool commands launched via a sibling helper), fall back to matching the caller's `ANTIGRAVITY_CONVERSATION_ID` (and `ORCA_AGENT_SESSION_ID` when present) against verified non-guessed Live Sessions, bound to Orca's verified caller identity. If parent-PID walk, `ANTIGRAVITY_CONVERSATION_ID` and `ORCA_AGENT_SESSION_ID` contradict each other, fail closed: omit `Reply:` and do not auto-deliver.
   - **Store-first, caller-identity gate and Chat-slot semantics**: every Message and verified screenshot is still saved first under `<state>/messages/` (ADR-0040). Direct Orca Chat delivery runs **only** when:
     1. The target is a non-guessed local `agy acp` Live Session (`ORCA_STRUCTURED_SESSION=1`) with a verified `orcaSessionId`.
     2. Right before sending, sideby performs a best-effort drift check on target `pid` + `procStart`, `ORCA_AGENT_SESSION_ID`, active `conversation_id` and title (skipping direct delivery to `paste-needed` when drift is detected). Because Orca 1.4.277 keeps the same `orcaSessionId` across `/clear` and `orca orchestration send` has no `conversation_id` precondition at enqueue time, direct delivery explicitly follows **Orca Chat-slot semantics** (targeting that live Orca Chat tab; a `/clear` in the race window cannot be atomically rejected by Orca, and is documented as a known boundary).
     3. The caller has a **verified Orca sender identity** (explicit `--from` from the caller's verified `ORCA_AGENT_SESSION_ID` or `ORCA_TERMINAL_HANDLE`). When `sideby send` is triggered from the Panel (`fromUser: true`) or a plain non-Orca terminal—where Orca has no explicit user-sender mode and would otherwise borrow an unrelated terminal—sideby skips Orca delivery and returns `paste-needed` with a plain-language note.
   - **Structured delivery outcome mapping**: writes the standard `sideby message <id> from <sender>` body (with screenshot paths and `Reply:` line when sender is verified) into an ephemeral mode-`0600` transport `body-file` (cleaned up after the child exits; the canonical Message file in `<state>/messages/` remains), and runs `orca orchestration send --to orca_session_id:<id> --from <verified-sender> --type status --subject <short> --body-file <file> --json --full` without a shell under a bounded timeout (`--type status` is passed explicitly because omitting `--type` fails with `runtime_error` on Orca Bot Chats; exact structured warning field for `recipient_delivery_held` to be confirmed against live `--json --full` output before shipping):
     - Parsed JSON `ok: true` confirming enqueue -> `delivered` (preserving any `recipient_delivery_held` warning in `note`).
     - Confirmed pre-send failure (missing `orca` binary, pre-delivery check failed, or structured error code proving the message never entered Orca's runtime, such as missing/stale recipient or explicit refusal) -> `paste-needed`.
     - Timeout after child launch, `runtime_unavailable`, `outcome_unknown`, or non-zero exit / unparseable output after send started -> `unknown` (ADR-0065: never tell the user to blindly paste again and never auto-retry).
   - Non-Orca terminal `agy` sessions (and any guessed session) stay on store-first + `paste-needed` until `agy` offers a documented cross-process inbound channel.
   - Read receipts check the tail of the receipt's stored `transcript` path (`brain/<id>/.system_generated/logs/transcript.jsonl`, treating `ENOENT` as not yet read) for `sideby message <id>` via `tailLinesWith`.
4. **Generic Orca plugin in `mods/orca/`**:
   - Ships alongside `mods/claude/` inside the `sideby` repository as a general, user-neutral Orca plugin (`engines.orca >= 1.4.248`), to be added to `package.json`'s `files` allowlist (and verified with `npm pack --dry-run` during implementation) with its install command documented.
   - Its `trusted-worker` reads `sideby sessions --json`, matches Orca's active Chat by `orcaSessionId`, updates an Orca `statusBarItems` entry with the current Session Label, and passes only the minimal display/copy fields to a TSX `components` sidebar panel with one-click "Copy for AI" and "Copy session id" actions.

## Considered

- **Writing `statusLine` directly into `~/.gemini/antigravity-cli/settings.json`**: violates sideby's Host-directory invariant when `--settings <file>` already applies per-session without touching the Host directory.
- **Letting Panel or plain CLI call `orca orchestration send` without a verified sender**: reproduced on Orca 1.4.277 that omitting sender identity causes Orca to borrow an unrelated terminal or fail with `no_active_sender_terminal`; falling back to `paste-needed` keeps attribution truthful.
- **Treating any non-zero `orca` exit or `ok: false` as `paste-needed`**: reproduced `runtime_unavailable` / `outcome_unknown` on disconnect where the message may already have been enqueued; mapping ambiguous post-send outcomes to `unknown` avoids duplicate sends.
- **Accepting bare Orca UUIDs alongside `conversation_id`**: risks prefix/UUID ambiguity across two ID namespaces; requiring exact `orca_session_id:<id>` keeps addressing unambiguous.
- **Using `agy` lifecycle hooks (`PreInvocation`/`Stop`) to poll or deliver messages**: hooks run only during an active turn and cannot wake an idle session (the same reason ADR-0040 rejected hooks for Grok Build).
- **Reading `ANTIGRAVITY_CSRF_TOKEN` or calling undocumented language-server methods**: violates sideby's credential and public-channel invariants (ADR-0040).

## Consequences

- `sideby sessions`, the Panel's Sessions page and `skills/sideby/` gain visibility into local terminal `agy` and local Orca Antigravity Chat sessions, with Session Labels and copyable Session References, without leaking `orcaSessionId` into the browser Panel.
- Cross-session messaging (`sideby send`) delivers directly between Orca-hosted sessions and `agy` Chats via `orca orchestration send --body-file`, maps uncertain network/runtime failures to `unknown`, and safely falls back to store-first + paste from Panel, plain terminals, or for non-Orca `agy`.
- `schemas/sessions.json` gains one optional field (`orcaSessionId`), keeping `schemaVersion: 1`.
- `sideby agy-statusline` and `sideby agy-title` are internal entries exempt from `src/cli/skill-coverage.test.ts`, like `statusline-tap`.
- No Host account files in `~/.gemini/antigravity-cli/` are ever modified by sideby.
- Before implementation lands, four runtime behaviors currently marked `UNVERIFIED` must be checked on `agy` 1.5.18 + Orca 1.4.277+: `--settings` shallow-merge vs object-replace semantics, live Orca Chat delivery + `transcript.jsonl` verbatim `sideby message <id>` persistence, and `lsof` + SQLite + `orca agent list` latency under load.
