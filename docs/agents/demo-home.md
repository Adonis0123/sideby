# Demo HOME and README media

Read this before trying the CLI or the Panel by hand, retaking README media, or updating the README. Linked from `AGENTS.md` ("Read when").

`scripts/demo-home.ts` builds a throwaway HOME with fake accounts (claude main, work and a DeepSeek API account; codex main and team; grok main and lab with one fixable Finding; pi main), fake Host binaries, usage records and cached quota. Use it to retake the README screenshots and to try the CLI or the Panel by hand without touching the real HOME:

```sh
node scripts/demo-home.ts /tmp/sideby-demo normal      # or empty | error | slow | resets
HOME=/tmp/sideby-demo/home XDG_CONFIG_HOME=/tmp/sideby-demo/home/.config \
  XDG_STATE_HOME=/tmp/sideby-demo/home/.local/state PATH=/tmp/sideby-demo/bin:$PATH node src/cli/main.ts ui
```

`empty` has Host binaries but no accounts; `error` and `slow` add a local plugin Family whose reader fails or answers after 6 s, for the Panel's error and loading states; `resets` is `normal` with a Codex account that holds a Limit Reset and one whose quota check stopped answering three hours ago, for the Limit Reset note, old numbers and using a reset. There `codex:main` holds one Limit Reset, and the fake `codex` answers the request that uses one (`account/rateLimitResetCredit/consume`), keeping what it "used" in `<dir>/codex-demo.json`, outside every Host directory, so `sideby quota reset codex:main --yes` and the Panel's confirmation can be tried there; write `reset` (the default), `nothing`, `none` or `hang` to `<dir>/codex-consume-mode` to choose its answer. Try using a reset only in a demo HOME: against a real Codex it cannot be undone. The script recreates `<dir>`, and refuses a non-empty directory it did not create (it leaves a `.sideby-demo` marker). Set the XDG variables too, or a shell that already exports them would point the Panel at your real config and state. When the maintainer asks to update the README, in any words, follow `.claude/skills/readme-assets/SKILL.md`: it covers the copy and all media, not only the text. README media (Panel screenshots, menu bar pictures, demo GIF, banner, intro video) and the code each depends on are listed in `docs/assets/manifest.json`. `node scripts/readme-assets.ts` lists what may be stale since its last retake, and also `feat` commits since the README last changed; `npm version` runs it as `preversion` and only warns. The `readme-assets` skill (`.claude/skills/readme-assets/SKILL.md`) acts on that list: it retakes the screenshots (`node scripts/shoot-panel.ts`, light and dark, English and Chinese, 1280×860 from the `normal` variant) and the menu bar pictures (`node scripts/shoot-menubar.ts`, macOS: it opens the real menu with demo data over a plain backdrop) and the GIF (`node scripts/record-demo.ts`, a [Motion](https://motion.dev) scene in `docs/assets/demo.html` filled with real `sideby run` output, a Panel screenshot and a real Auto Handoff; needs ffmpeg, gifsicle and Chrome; `--frames 2,8` for a quick look; under 4 MB or GitHub may not show it) without asking, drafts copy changes, and asks before each paid retake of the banner (Codex image generation) or the intro video (`painted-animation`). Keep each README's `<picture>` block pointing at its own pair of screenshots. When a listed change does not affect a medium, `node scripts/readme-assets.ts --mark <id>` records that. The fixture Host is `scripts/demo-host.sh`; it is not Claude Code.
