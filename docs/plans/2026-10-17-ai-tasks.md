# AI Task（让 AI 帮我）实施计划

**目标**：实现 spec §3.28：面板和 CLI 能把任何任务交给用户自己的账号。sideby 打开首选终端，用 `sideby ask --run <task-id>` 启动宿主，带上 Task Prompt；另加 `sideby key`、`sideby try`、`sideby terminal`、`sideby plugins new|check`，以及面板的「登录」一键开终端。

**架构**：
- 纯函数 `taskPrompt`（`panel/page-logic.ts`）拼提示词，CLI 和面板共用。
- 新模块 `core/terminal.ts`：检测、猜测首选终端，生成每种终端的启动参数（纯函数），通过 `DesktopDeps.exec` 执行。
- 新模块 `core/ask.ts`：选账号、写或读任务文件、`--run` 时像 `run` 一样启动宿主。
- `core/secret-file.ts` 增加只写不读的 `setSecret`。
- 新模块 `core/probe.ts`：`try` 的执行与输出打码。
- 新模块 `plugins/scaffold.ts`、`plugins/check.ts`：插件骨架和校验。

**技术栈**：Node 22.18+ 直接运行 `.ts`；`node --test`；测试只用 `testing/` 的 `withFakeHome`、`fakeHost`；启动程序全部替换 `DesktopDeps.exec`，测试从不开真终端。

**依据**：spec §3.28、ADR-0027、ADR-0008、ADR-0001、ADR-0006、`CONTEXT.md`「Asking AI」。

## 全局约束

- 用户文字、路径不进 shell 或 AppleScript 字符串；字符串里只出现固定命令 `sideby ask --run '<id>'`，`<id>` 是 16 位十六进制，生成时校验。
- 任务文件 `$XDG_STATE_HOME/sideby/ask/<id>.json`：目录 700，文件 600，原子写；读后删除；超过 1 小时拒绝。
- 密钥只经 `sideby key` 和面板的密钥对话框写入；不进 Task Prompt、日志、`--json`、错误信息。Task Prompt 生成前删掉像密钥的串。
- 面板的 `/api/ask`、`/api/login`、`/api/key`、`/api/try` 都是写接口：token、Host、Origin 检查不变，只读面板 403。
- `try` 不加 `--yes` 退出 10；宿主输出最多 2KB，按 Secret File 的值打码。
- `FamilyDef.probe` 是公开契约的新增字段：只加不改，`schemaVersion` 不变。
- `--json` 带 `schemaVersion: 1`；改了 `--json` 或 config 就跑 `pnpm schemas`，并更新 `llms.txt`。
- 用户可见的错误都说下一步怎么做；面板文案中英两份同步。
- 用户没要求就不 commit；各任务末尾的提交信息留作之后提交时用。

## 重点检查（各任务测试要覆盖的输入）

1. 用户文字里有 `'`、`"`、`$(…)`、反引号、换行、`; rm`：生成的终端参数里都不出现，宿主收到的是原文（一个参数）。对应任务 2、3。
2. 用户文字里有 `sk-…` 长串：Task Prompt 里已删掉，并给出提示。对应任务 1。
3. 任务文件被改成 644、过期、id 不合法、指向另一个目录：`--run` 都拒绝。对应任务 3。
4. 没有已登录账号、所有账号都用完、只有 API 账号：选号结果和面板的退路。对应任务 3、7。
5. `sideby key` 不在终端里运行（stdin 是管道）时拒绝；写入后 `proxy.env` 其他行逐字节不变；输出和 `--json` 里没有值。对应任务 4。
6. `try` 的宿主输出里出现了密钥值：已替换成 `***`。对应任务 5。
7. `plugins check` 遇到 `..` 路径、绝对路径、真实 HOME 路径、邮箱时，各给一条带修法的问题。对应任务 6。
